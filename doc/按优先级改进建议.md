# FF-PLAEY 按优先级改进建议

## 目标

本文档用于指导当前播放器项目的后续改进工作，优先顺序遵循以下原则：

1. 先解决会导致功能错误、体验异常、跨环境失效的问题。
2. 再解决会限制后续扩展的结构问题。
3. 最后补齐工程化、发布和长期维护能力。

---

## P0：立即处理

这一层的问题会直接影响播放器是否“能正确工作”。

### 1. 修正音频倍速未真正生效的问题

当前界面已经提供 0.5x、0.75x、1.0x、1.25x、1.5x、2.0x 倍速菜单，但实际代码中没有真正接入 `atempo` 或其他音频变速链路。

现状：

- `MainWindow` 中假设音频倍速已由解码器处理。
- `VideoDecoder` 中只实现了音频重采样，没有实现音频变速滤镜。
- 这会导致“视频按倍速走、音频仍按原速或同步逻辑不稳定”。

建议：

- 在 `VideoDecoder` 中引入 FFmpeg 音频滤镜链。
- 使用 `abuffer -> atempo -> abuffersink` 处理解码后的音频帧。
- 将倍速切换设计为可重建音频滤镜链的流程。
- 在倍速切换时清空旧的音频缓冲，避免切换后短时间内仍播放旧速率数据。

验收标准：

- 0.5x 到 2.0x 都能正常发声。
- 音调不明显失真。
- 倍速切换后音画不会快速漂移。

### 2. 修正音频时钟计算与真实输出格式不一致的问题

当前 `AudioOutputDevice` 使用固定值 `176400 bytes/s` 计算当前音频 PTS，这隐含假设输出格式永远是：

- 44100 Hz
- 16-bit
- 双声道

但主窗口中当默认音频设备不支持该格式时，会退回设备首选格式。这意味着：

- 实际输出格式可能不是 44100/16bit/2ch
- 音频时钟将被错误计算
- 音画同步会出现系统性偏差

建议：

- 将音频格式信息从 `QAudioFormat` 传入 `AudioOutputDevice`。
- 基于真实 `sampleRate`、`channelCount`、`sampleFormat` 计算 `bytesPerSec`。
- 不要在 `AudioOutputDevice` 中硬编码格式常量。

验收标准：

- 更换不同输出设备后，同步逻辑仍成立。
- 进度条和实际听到的音频位置基本一致。

### 3. 修正仅支持“必须有视频流”的打开逻辑

当前文件选择器允许打开 `mp3/aac/wav`，但 `VideoDecoder::open()` 如果没有视频流会直接失败。

这会导致：

- UI 告诉用户支持音频文件
- 实际实现却拒绝纯音频媒体

建议二选一：

1. 如果短期内只做视频播放器，就把文件选择器过滤条件收紧为视频格式。
2. 如果要保留音频文件支持，就补齐“纯音频模式”：
   - 没有视频流也允许打开
   - 视频区域显示封面或占位图
   - 进度条、时间、倍速、暂停等逻辑继续有效

建议优先采用第 1 种，先保证行为一致。

验收标准：

- 用户看到的“支持格式”与实际能力一致。

### 4. 去除硬编码绝对路径资源

当前暂停浮层图标使用了硬编码绝对路径，项目一旦换目录、换机器、换用户就会失效。

建议：

- 所有图片资源统一从 `icon.qrc` 加载。
- 禁止在业务代码中写死 `D:\...` 形式路径。

验收标准：

- 项目拷贝到另一台机器后，资源仍可正常显示。

## P1：高优先级

这一层的问题不会立刻让功能失效，但会持续影响稳定性和用户体验。

### 5. 改善 seek 与拖动预览时的界面卡顿

当前拖动进度条时会周期性同步调用 `loadPreviewFrame()`。对于高码率视频、长视频或关键帧稀疏视频，这种方案容易阻塞 UI。

建议：

- 将预览帧加载改成异步任务。
- 新的拖动请求到达时，取消或丢弃旧请求。
- 对预览增加节流和去抖，避免短时间内高频 seek。

验收标准：

- 快速拖动进度条时窗口不会明显卡死。
- 预览响应可以略延迟，但不能拖垮界面线程。

### 6. 提升音画同步精度

当前主时钟主要依赖：

- `AudioOutputDevice` 中按已读字节数估算的音频 PTS
- `MainWindow` 中基于该 PTS 做视频帧调度

问题在于：

- 没有扣除 `QAudioSink` 内部缓冲延迟
- 估算值接近“写给音频设备的数据位置”，未必等于“真正已经播出的声音位置”

建议：

- 结合 `QAudioSink` 缓冲状态估算真实播放延迟。
- 区分“已送入缓冲的数据时间”和“已经出声的时间”。
- 对视频渲染调度增加漂移校正策略，而不是只依赖固定阈值丢帧。

验收标准：

- 长时间播放时音画不明显漂移。
- 暂停、继续、seek 后恢复同步更稳定。

### 7. 统一编码和资源命名策略

当前项目中存在中文文件名、界面文本和注释；从读取结果看，已经出现乱码现象。这说明编码管理不稳定。

建议：

- 统一源码与文档编码为 UTF-8。
- 明确 Qt 工程、编辑器、终端的编码规范。
- 资源文件名建议逐步改成 ASCII 命名，例如 `play.png`、`pause.png`、`app_icon.png`。
- 中文显示文本保留在源码中可以，但文件名和路径更适合英文。

验收标准：

- 不同机器、不同工具打开源码和 UI 文件不再乱码。

## P2：结构优化

这一层主要解决“代码能写下去，但越来越难维护”的问题。

### 8. 拆分过重的 MainWindow

当前 `MainWindow` 同时承担了：

- UI 初始化
- 打开文件
- 播放控制
- 倍速菜单
- 音频链路创建和销毁
- 渲染队列管理
- 主时钟逻辑
- seek 流程控制

这会让后续加功能时改动范围过大。

建议拆分为至少三个职责块：

1. `MainWindow`
   - 只负责界面交互和显示
2. `PlaybackController`
   - 负责播放状态切换、seek、倍速、时钟协调
3. `AudioRenderer` / `RenderScheduler`
   - 负责音频输出管理或视频调度

验收标准：

- `MainWindow` 不再直接管理过多底层细节。
- 播放逻辑更容易测试和复用。

### 9. 解耦解码与渲染数据通道

当前 `VideoDecoder` 同时负责：

- 打开媒体
- 解码视频
- 解码音频
- 像素格式转换
- 音频重采样
- 预览 seek
- 播放节奏控制

这会让 `VideoDecoder` 演变成全能类。

建议：

- 保持 `VideoDecoder` 只负责 demux + decode。
- 将视频格式转换抽离到单独模块。
- 将音频后处理抽离到单独模块。
- 将节奏控制从解码线程中进一步挪到调度层。

验收标准：

- 解码器只关心“产出帧”，不关心“何时播放”。

### 10. 明确线程模型和状态机

当前项目已经使用了解码线程、UI 线程和音频回调读取，但播放状态仍以多个布尔变量组合控制，边界不够清晰。

建议：

- 定义明确状态机：`Idle / Opened / Playing / Paused / Seeking / Stopped / Ended / Error`
- 每个状态允许什么操作、操作后转到哪个状态，要写清楚。
- 统一 stop、pause、seek、open 的生命周期处理流程。

验收标准：

- 连续点击播放、暂停、停止、拖动时，不容易进入异常状态。

## P3：工程化完善

这一层主要面向团队协作、发布和长期维护。

### 11. 清理仓库结构

当前仓库根目录混入了：

- `build/`
- `CMakeLists.txt.user`
- 文档
- 资源
- 源码

建议目录结构：

```text
FF-PLAEY/
  src/
  include/
  resources/
  3rdparty/
  doc/
  tests/
  CMakeLists.txt
```

建议：

- `doc/` 只放文档
- `resources/` 放图片、qrc
- `src/` 放 `.cpp`
- `include/` 放 `.h`
- 构建产物排除出仓库

### 12. 增加 README 和构建说明

当前项目缺少基础说明，外部接手者很难快速复现环境。

至少应包含：

- 项目简介
- Qt 版本
- 编译器要求
- FFmpeg 依赖说明
- 构建步骤
- 运行方式
- 当前已知限制

### 13. 增加 `.gitignore`

当前本地构建产物和用户配置文件已经进入项目目录。需要尽快添加 `.gitignore`，避免后续仓库继续污染。

至少忽略：

- `build/`
- `*.user`
- `CMakeCache.txt`
- `CMakeFiles/`
- 可执行文件、调试符号、中间产物

### 14. 补充基础测试

当前没有自动化测试。

建议先从最容易落地的部分开始：

- 时间格式化函数测试
- 媒体信息提取测试
- seek 边界测试
- 音频格式换算测试
- 状态机测试

短期即便无法做完整集成测试，也应先建立单元测试基础。

## 推荐执行顺序

建议按以下顺序推进：

1. 修正倍速音频链路
2. 修正音频时钟格式硬编码
3. 统一“支持格式”和实际打开逻辑
4. 清理硬编码资源路径
5. 优化拖动预览卡顿
6. 提升音画同步精度
7. 统一编码和资源命名
8. 拆分 `MainWindow`
9. 解耦 `VideoDecoder`
10. 明确状态机
11. 清理仓库结构并固定 `doc/` 目录用途
12. 增加 `README`
13. 增加 `.gitignore`
14. 补基础测试

---

## 阶段性目标建议

### 第一阶段：做成“功能正确的播放器”

范围：

- P0 全部完成
- P1 中的 seek 卡顿和同步精度至少完成一版

结果：

- 播放、暂停、停止、seek、倍速都能稳定工作

### 第二阶段：做成“能继续扩展的播放器”

范围：

- 完成 P2

结果：

- 后续增加音量、全屏、字幕、播放列表时代码不会失控

### 第三阶段：做成“可协作维护的项目”

范围：

- 完成 P3

结果：

- 新成员能快速上手
- 仓库更干净
- 发布和回归更可控

---

## 当前结论

这个项目已经具备播放器原型的主链路，但当前最需要优先解决的不是“继续堆功能”，而是：

- 倍速是否真的正确
- 音频时钟是否可信
- 支持格式是否和真实能力一致
- 资源与编码是否能跨机器稳定工作

如果以上问题不先收口，后续继续叠加功能会放大维护成本和调试难度。
